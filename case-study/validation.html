04 · VALIDATION PLAN

데이터가 없다는 사실을 숨기지 않고,
검증 가능한 구조를 만듭니다.

이번 리뉴얼은 실제 사용자 데이터가 충분한 프로젝트가 아닙니다. 따라서 관찰을 사실처럼 포장하지 않고 가설로 기록하고, 사용성 테스트와 상담 폼을 통해 다음 데이터가 쌓이도록 설계합니다.

사용성 테스트

TASK 01

서비스 찾기

“민간자격을 등록하려고 합니다. 어떤 서비스를 이용해야 하는지 찾아보세요.”

관찰: 선택 시간, 망설임, 잘못 선택한 메뉴

TASK 02

필요 정보 이해

“민간자격 등록을 위해 무엇을 준비해야 하는지 찾아보세요.”

관찰: 이해 여부, 어려운 표현, 추가 질문

TASK 03

업무사례 찾기

“나와 비슷한 민간자격 등록사례를 찾아보세요.”

관찰: 메뉴 이해, 스크롤 횟수, 필터 사용

TASK 04

상담 시작

“상담이 필요하다고 판단했습니다. 상담을 시작해보세요.”

관찰: CTA 발견, 클릭 수, 작성 부담, 전화 선택 여부

리뉴얼 이후 쌓을 수 있는 데이터

업무 유형어떤 서비스 문의가 많은가
진행 단계처음 문의인지, 진행 중 문제인지
신청 주체개인 / 사업자 / 법인·단체
상담 행동전화 / 맞춤문의 중 무엇을 선택하는가

폼을 단순 전환 장치가 아니라
리서치 장치로 사용합니다.

사용자 가치

  • 빈 게시판보다 작성 부담이 낮음
  • 전문 용어를 몰라도 문의 가능
  • 상담 전에 자신의 상황을 정리할 수 있음

비즈니스 가치

  • 상담 전 기본정보 확보
  • 반복적인 기초 질문 감소 가능성
  • 문의 유형 데이터의 구조화
  • 이후 페이지 개선의 근거 확보

포트폴리오에서 이렇게 표현합니다.

“데이터가 충분하지 않은 상황에서 문제를 사실로 단정하지 않고 관찰을 기반으로 가설을 수립했다. 이후 정보구조와 상담 플로우를 설계하고, 사용성 테스트와 구조화된 문의 데이터를 통해 검증할 수 있도록 설계했다.”
