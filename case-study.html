01 / Website Renewal

Information structure & responsive build

정리되지 않은 자료와 기존 구조를 검토하고, 정보 우선순위와 모바일 사용성을 기준으로 UI를 다시 설계한 뒤 반응형 웹으로 직접 구현한 리뉴얼 작업.

RoleScope · Planning · UI · Publishing · CMSStackHTML · SCSS · JavaScriptPlatformWeb / Mobile
LIVE PROJECT IMAGEResponsive Web

Context

자료와 기존 구조를 먼저 정리해야 했습니다.

전달받은 자료만으로는 바로 화면을 구성하기 어려웠고, 기존 메뉴도 방문자 관점에서 우선순위가 명확하지 않았습니다. 기존 사이트와 업종 특성을 함께 검토해 콘텐츠 범위와 페이지 구성을 다시 정리했습니다.

Problem

01

메뉴와 콘텐츠의 우선순위가 불분명

02

모바일에서 주요 정보 탐색이 어려움

03

제공 자료를 그대로 사용하기 어려움

My Decision

방문자의 탐색 순서를 기준으로 구조를 다시 잡았습니다.

기존 메뉴 체계를 그대로 따르지 않고 주요 문의 목적과 정보의 성격을 기준으로 메뉴를 재구성했습니다. 모바일에서는 정보량과 버튼 배치를 조정해 핵심 동선이 먼저 보이도록 정리했습니다.

Design → Build

설계한 화면을 직접 구현하면서 실제 환경에 맞게 다시 조정했습니다.

DESIGN
FIGMA / UI IMAGE

정보 구조와 우선순위를 바탕으로 PC와 모바일 UI를 구성했습니다.

BUILD
LIVE / BUILD IMAGEHTML · SCSS · JS

반응형으로 직접 구현하고 CMS에 적용하면서 실제 환경에서 필요한 부분을 다시 조정했습니다.

Responsive

PC 화면을 단순 축소하지 않고 모바일 정보 우선순위와 인터랙션을 다시 조정했습니다.

Interaction

JavaScript와 jQuery를 활용해 필요한 동작과 화면 상태를 구현했습니다.

CMS

운영자가 수정해야 하는 영역은 실제 관리 환경과 유지보수성을 함께 고려했습니다.

After Launch

오픈 이후의 피드백도 다시 화면에 반영했습니다.

운영 중 들어오는 수정 요청과 오류를 확인해 실제 화면에 반영하고, 반복되는 이슈는 이후 프로젝트에서 동일한 문제가 생기지 않도록 작업 기준에 반영했습니다.

What I learned

디자인과 구현을 함께 경험하면서 판단 기준이 달라졌습니다.

UI를 직접 구현하고 운영까지 이어서 경험하면서 디자인 단계에서부터 반응형 동작, 구현 제약, CMS 구조와 이후 수정 가능성을 함께 보는 기준이 생겼습니다.
