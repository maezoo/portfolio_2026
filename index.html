01 / Real Work

Website Renewal 01

자료와 메뉴가 정리되지 않은 상태에서 시작해, 기존 사이트와 업종을 다시 확인하고 정보의 우선순위부터 정리한 리뉴얼 작업입니다.

Context

제공된 자료만으로 바로 화면을 만들기 어려웠고, 기존 메뉴 역시 방문자보다 내부 기준에 가까웠습니다.

Problem

  • 메뉴와 콘텐츠의 우선순위가 분명하지 않았음
  • 모바일에서 원하는 내용을 찾기 어려웠음
  • 기존 자료를 다시 분류해 사용할 필요가 있었음

My Decision

전달받은 메뉴를 그대로 사용하지 않고 기존 사이트와 업종을 다시 확인했습니다. 방문자가 먼저 찾을 내용을 기준으로 메뉴를 나누고, 중요한 정보와 문의 동선을 앞쪽에 배치했습니다.

Design & Build

PC와 모바일 UI를 정리한 뒤 반응형으로 직접 구현하고 CMS에 적용했습니다.

My Role

요청 확인 · 범위 정리 · 견적 · 일정 조율 · 콘텐츠 정리 · UI · 퍼블리싱 · CMS · 검수 · 오픈

02 / Real Work

Website Renewal 02

여러 페이지에 흩어져 있던 내용을 다시 묶고, 주요 서비스와 문의까지 더 빠르게 이어지도록 정리한 작업입니다.

Context

비슷한 내용이 여러 메뉴에 반복되어 있었고, 처음 방문했을 때 어디부터 봐야 할지 바로 알기 어려웠습니다.

My Decision

콘텐츠를 목적별로 다시 묶고 주요 서비스를 먼저 보여주도록 순서를 조정했습니다. 모바일에서도 같은 기준이 유지되도록 정보량과 버튼 위치를 다시 정리했습니다.

After Launch

오픈 이후 들어오는 고객 피드백과 오류를 확인해 실제 화면에 반영하고, 유지보수 과정에서 반복되는 문제를 다음 작업 기준에 반영했습니다.

My Role

요구사항 정리 · 페이지 구성 · UI · 반응형 구현 · CMS · 고객 피드백 · 유지보수

03 / Personal Project

Product Case Study

실무에서 상대적으로 적게 다뤘던 사용자 리서치와 검증 과정을 보완하기 위한 개인 프로젝트입니다.

Process

Research→Problem→Hypothesis→Prototype→Test→Iterate

Focus

완성된 화면 하나를 만드는 것보다, 실제 사용 과정에서 어디서 막히는지 확인하고 그 결과를 다음 화면에 반영하는 과정을 중심으로 구성합니다.

How I Work

Define.
Build. Improve.

툴 자체보다 실제 프로젝트에서 어디까지 판단하고 실행해왔는지를 보여주는 영역입니다.

01 / Define

Scope & Planning

신규 제작, 리뉴얼, 부분 수정 요청을 확인해 필요한 범위와 견적, 일정을 정리합니다. 자료가 부족하면 기존 사이트와 업종을 확인해 콘텐츠와 페이지 구성부터 다시 잡습니다.

02 / Design

UI Design

무엇을 먼저 보여줄지 정리한 뒤 웹과 모바일 화면으로 옮깁니다. Figma는 이 과정을 정리하는 도구로 사용합니다.

03 / Build

Implementation

HTML, SCSS, JavaScript, jQuery로 반응형 화면을 직접 구현하고 CMS에 적용합니다. 시맨틱 구조, 웹 표준, SEO, 크로스브라우징과 유지보수성도 함께 확인합니다.

04 / Improve

Operation & Iteration

오픈 이후 수정 요청과 오류, 고객 피드백을 확인해 화면에 반영합니다. 반복되는 문제는 다음 작업에서 다시 생기지 않도록 기준으로 정리합니다.

Why this experience matters

디자인과 구현,
운영 사이를 연결합니다.

요청 확인부터 기획, UI, 구현, 오픈과 유지보수까지 한 프로젝트의 여러 단계를 직접 경험했습니다. 그래서 화면을 설계할 때 디자인만 따로 보지 않고 실제 구현 방식과 운영 환경까지 함께 생각합니다.

01

Implementation-aware

직접 구현해온 경험 덕분에 디자인 단계에서 반응형, CMS, 인터랙션 등 실제 적용 과정에서 생길 문제를 미리 확인할 수 있습니다.

02

Less handoff gap

디자인과 구현을 분리해서 생각하지 않아 개발 과정에서 필요한 정보와 제약을 더 빠르게 이해하고 조정할 수 있습니다.

03

Built to improve

오픈을 끝으로 보지 않고 운영 중 들어오는 피드백과 오류를 다시 화면에 반영해왔습니다. Product Designer로서는 이 경험을 더 빠른 검증과 개선에 연결하고 싶습니다.
