Website Renewal

정리되지 않은 자료와 메뉴에서 출발해, 방문자가 필요한 정보를 먼저 찾도록 구조를 다시 설계하고 반응형 웹으로 구현했습니다.

Context

제공된 자료만으로 바로 화면을 만들기 어려웠고 기존 메뉴도 내부 기준에 가까웠습니다.

Problem

콘텐츠 우선순위가 불분명했고 모바일에서 주요 정보와 문의 동선을 찾기 어려웠습니다.

My Decision

업종과 기존 사이트를 다시 살펴 방문 목적별로 메뉴를 나누고, 핵심 정보와 문의를 앞쪽에 배치했습니다.

Design → Build

PC·모바일 UI를 정리한 뒤 반응형으로 직접 구현하고 CMS에 적용했습니다.

After Launch

실제 콘텐츠가 들어간 뒤의 줄바꿈과 모바일 가독성을 확인해 세부 화면을 보완했습니다.

Improve

반복 수정이 필요한 영역을 컴포넌트 기준으로 정리해 이후 운영의 부담을 줄였습니다.

서비스 정보 구조
Website Renewal

여러 페이지에 흩어진 내용을 목적별로 다시 묶고, 주요 서비스에서 문의까지 더 짧게 이어지도록 정리했습니다.

Context

비슷한 내용이 여러 메뉴에 반복되어 처음 방문한 사용자가 어디부터 봐야 할지 알기 어려웠습니다.

Problem

서비스 설명과 문의 동선이 분리되어 탐색 단계가 길고 모바일의 정보 밀도가 높았습니다.

My Decision

콘텐츠를 방문 목적별로 다시 묶고 주요 서비스의 순서와 버튼 위치를 동일한 기준으로 정리했습니다.

Design → Build

콘텐츠 양에 대응하는 유연한 레이아웃으로 설계하고 CMS 환경에서 직접 구현했습니다.

After Launch

오픈 이후 고객 피드백과 오류를 확인해 실제 화면에 반영했습니다.

Improve

운영 중 반복된 문제를 체크리스트로 남겨 다음 프로젝트의 설계와 검수 기준에 반영했습니다.

Product Case Study

실무에서 상대적으로 적게 다뤘던 사용자 리서치와 검증 과정을 보완하기 위한 개인 프로젝트입니다.

Context

구현 가능한 화면을 만드는 경험을 넘어, 사용자 행동을 근거로 문제를 정의하는 연습이 필요했습니다.

Problem

가정만으로 완성도를 높이기보다 실제 사용 과정에서 막히는 지점을 확인해야 했습니다.

My Decision

리서치 → 문제 정의 → 가설 → 프로토타입 → 테스트 순서로 판단 근거를 남겼습니다.

Design → Build

핵심 행동을 빠르게 확인할 수 있는 범위로 프로토타입을 설계했습니다.

After Test

의도한 흐름과 실제 행동의 차이를 기록하고 우선순위를 다시 조정했습니다.

Improve

검증 결과를 다음 화면에 반영해 한 번의 결과물이 아닌 반복 과정으로 정리합니다.
