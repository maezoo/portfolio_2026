01

Context

페이지는 많았지만
어디부터 봐야 할지 모호했습니다.

비슷한 내용이 여러 메뉴에 반복되어 있었고, 처음 방문한 사용자가 필요한 서비스를 찾으려면 여러 페이지를 오가야 했습니다. 콘텐츠를 줄이는 것보다 먼저, 사용자의 목적에 맞게 다시 묶는 일이 필요했습니다.

02

Problem

서비스 이해와 문의가
하나의 흐름으로 이어지지 않았습니다.

반복되는 설명

유사한 정보가 여러 메뉴에 분산되어 각 페이지의 역할이 모호했습니다.

길어진 탐색

핵심 서비스를 이해한 뒤 문의로 이동하기까지 단계가 많았습니다.

높은 모바일 밀도

작은 화면에서도 PC와 같은 정보량이 노출되어 읽는 부담이 컸습니다.

03

My Decision

페이지 기준이 아니라
방문 목적을 기준으로 다시 묶었습니다.

콘텐츠를 사용자가 알고 싶은 내용과 다음에 할 행동을 기준으로 재분류했습니다. 주요 서비스를 먼저 보여주고 각 설명 뒤에 동일한 문의 기준을 적용해, 어느 경로에서도 자연스럽게 다음 행동으로 이어지도록 했습니다.

중복 콘텐츠 확인→목적별 정보 재분류→문의 동선 연결
04

Design → Build

콘텐츠가 달라져도
같은 기준이 유지되도록.

콘텐츠 양에 유연하게 대응하는 레이아웃으로 설계하고 CMS 환경에서 직접 구현했습니다. 모바일에서는 설명을 단순히 줄이는 대신 제목, 핵심 정보, 행동 버튼의 순서가 유지되도록 정보 밀도를 조정했습니다.

STRUCTURE일관된 정보 위계

서비스마다 같은 읽기 흐름을 적용해 비교와 탐색이 쉬워지도록 했습니다.

RESPONSIVE모바일 우선순위

작은 화면에서 중요한 내용과 행동이 먼저 보이도록 순서를 다시 구성했습니다.

05

After Launch

운영에서 들어온 피드백을
실제 화면에 반영했습니다.

오픈 이후 고객 피드백과 오류를 확인해 콘텐츠와 화면을 수정했습니다. 기획 당시의 예상보다 실제 운영에서 자주 바뀌는 영역을 파악하면서 다음 설계에서 고려해야 할 기준도 더 구체적으로 정리할 수 있었습니다.

06

Improve

반복되는 문제를
다음 프로젝트의 기준으로 만들었습니다.

유지보수에서 반복된 문제를 검수 체크리스트로 남겼습니다. 콘텐츠 길이, 모바일 버튼 위치, CMS 입력 예외를 다음 프로젝트에서 더 일찍 확인하면서 설계와 구현 사이의 왕복을 줄였습니다.
